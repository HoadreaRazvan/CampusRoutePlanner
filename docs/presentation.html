02 Client & problem

A route that obeys the day's constraints

  • A directed campus graph read from CSV: buildings, one-way connections and travel time in minutes.
  • Temporary closures. Some connections are blocked for a single request, e.g. A>G;B>G.
  • A required visit. Keys, a tool or a permit must be picked up before reaching the work site.
  • The answer is the minimal total travel time and the route, or a clear NO_FEASIBLE_ROUTE.
  • Bad input is refused: missing columns, unknown buildings, negative travel times.
BoundaryThe planner only knows the graph it is given. It cannot check whether a real path on campus is open or safe. No GPS, no live maps.

04 The key decision

One building, two states

Arriving at the Lab before the Kitchen pickup is not the same as arriving after it: the work left to do is different. So every building lives on two layers of the search.

  • At most 2·|V| states: 22 on graph2, 24 on graph3. Exact and still cheap.
  • A route may revisit a building when the flag has changed: … Lab → Kitchen → Lounge → Lab, 12 min.
  • Brief's question: are two routes to the same building equivalent if only one has made the visit? No. They are different states.
With state = building only: Lab is closed at g = 9, before the pickup. The return to Lab after the Kitchen is pruned, and the planner wrongly answers NO_FEASIBLE_ROUTE.

05 The two methods

One engine, two strategies

UCS and A* share a single best-first search. It always expands the state with the lowest f = g + h. Only the heuristic h differs.

With h = 0, f = g: the same queue order, the same expanded states, the same route. A* with h = 0 is UCS, and the tests check it on every request.
src/search/best_first.py · condensedUCS: h = 0 · A*: h = distance / vmax
def best_first_search(graph, start, goal, h, required=None, blocked=()):    start_state = State(start, required is None or start == required)    frontier = [(h(start), 0.0, 0, start_state)]    # (f, g, tie-break, state)1    best_g, parent, closed = {start_state: 0.0}, {start_state: None}, set()    while frontier:        f, g, _, state = heapq.heappop(frontier)        if state in closed: continue          # stale entry, not counted2        closed.add(state); expanded += 1        if state.node == goal and state.visited:  # goal test on removal3            return rebuild(parent, state), g, expanded        for edge in graph.get_neighbors(state.node, blocked):            child = State(edge.to, state.visited or edge.to == required)4            new_g = g + edge.minutes            if child in closed or new_g >= best_g.get(child, inf): continue            best_g[child], parent[child] = new_g, state            counter += 1            heapq.heappush(frontier, (new_g + h(edge.to), new_g, counter, child))    return NO_FEASIBLE_ROUTE
  • 1Deterministic ties on (f, g, insertion order): the same input expands the same states on every machine (ADR-02, ADR-07).
  • 2Expanded states = states removed and expanded. Outdated duplicates are skipped and not counted (ADR-05).
  • 3Goal test on removal, so no cheaper route is still waiting in the queue. Matters for zero-cost edges (ADR-04).
  • 4The flag flips when the walk enters the required stop, and stays set (AC-01, AC-03).

07 The heuristic

Checked against the data, not assumed

h(n) = straight_line(n, goal) / vmax

Client note: nobody walks faster than 80 m/min in a straight line. Coordinates in nodes.csv are in metres.

admissible: walk ≥ straight line, speed ≤ vmax
⇒ h(n) ≤ h*(n)
consistent, for every edge n → m with time c:
h(n) ≤ d(n,m)/vmax + h(m) ≤ c + h(m)

The second inequality holds only if no edge is faster than vmax. That is a property of the data, so check_consistency tests all 34 edges before A* uses h. One failure means A* falls back to h = 0 and says why.

08 Research task

The six questions, answered

Choosing what to explore
How does each method pick the next state?

UCS takes the lowest g. A* takes the lowest g + h. Ties go by (f, g, insertion order), so runs are reproducible.

Optimality
When is the answer optimal?

UCS: all costs ≥ 0. A*: h admissible for tree search, consistent for graph search with a closed set. In both cases the goal test runs when the state leaves the queue.

Zero heuristic
What does A* do with h = 0?

It becomes UCS exactly: the same path, cost and number of expanded states. Verified on all 22 requests.

Available information
Is a non-zero heuristic useful here?

Only graph2 has coordinates. There it cuts expansions from 77 to 59. graph1, graph3 and probably the hidden graph have none, so A* runs with h = 0.

Constraints
How do the constraints change the search?

Closures remove actions for one request. The required stop doubles the state space and moves the goal to (goal, True).

Fair comparison
How do we compare the methods fairly?

Same code path, only h changes. Cost, expanded states and runtime reported separately. Runtime = search only, median of 50 runs. The benchmark fails if costs ever differ.

13 Limitations & lessons

A more complex method does not automatically produce a better result.

On graph1 and graph3 A* is UCS: without coordinates there is nothing to build a heuristic from. Where the data supports it (graph2), A* saves 23 % of the work and never changes an answer.

  • Supplied graph onlyWe cannot tell whether a corridor is really open or safe.
  • One required stopSeveral stops would need a set of visited stops in the state, up to 2k flags, or a fixed order.
  • One of several best routesEqual-cost routes exist (three of 9 min in graph3). We return one, deterministically.
  • Heuristic qualityIt ignores closures and the pending stop. A stronger admissible option: (d(n, stop) + d(stop, goal)) / vmax while the stop is pending.
  • Data-dependent hWrong coordinates or vmax trigger the fallback to h = 0: always correct, only slower.
  • RuntimesMeasured on one machine; comparable only within the same run.

What does the system need to know to tell a valid solution from an invalid one?

Four things: every step is a real edge that is not closed for this request; the required stop appears before the route ends; it ends at the goal; and the reported cost equals the sum of the edge times. That is the flag in the state, and exactly what our independent route checker tests.
